# Stadtstack Data

Standalone Node.js ≥22 city-data collector and read-only open-data/MCP publisher. No Next.js dependency and no resident location is collected or persisted. All outputs cover a **whole city**, including road corridors up to ~25 km outside its bounds; resident-home filtering must happen on the resident's device. The optional MCP spatial searches see the query **where the MCP runs**: on a local machine, it stays local; a hosted MCP operator would see the coordinates submitted to that host.

## Run

```sh
npm install
npm run quality:refresh -- --retain-city-snapshot
npm run knowledge:prepare             # stage completed joint extraction
npm run publish                       # validates before replacing outputs
npm run all                           # retained city snapshot + staged knowledge + publication
npm test
npm run mcp                           # stdio
npm run mcp:http                      # Streamable HTTP http://127.0.0.1:4318/mcp
```

For hosted Jev evaluation, save `TYPESAFE_API_KEY` in `stadtstack-data/.env.local` (copy `.env.example`; leave the key out of commands and logs) and restrict permissions with `chmod 600 stadtstack-data/.env.local`. Both root and package-local `.gitignore` ignore `.env.local`; only the blank-key template is tracked. `npm --prefix stadtstack-data run jev:check` reports key presence only, verifies the evaluator environment and, when the key is present, locally constructs the selected Jev metric without sending a request. `FAITHFULNESS_MODE` defaults to `llm`; set `hybrid` or `system_one` in `.env.local` to opt into DeepEval 4.x's Jev integration. `hybrid` uses the repository Codex judge for LLM extraction/reasoning plus Jev decisions; `system_one` uses Jev without an LLM. A real call occurs only when evaluator runs on candidate source text. Production remains `llm` with `penalize_ambiguous_claims=True`; the dated [live Jev calibration](../docs/research/FAITHFULNESS_JEV_EXPERIMENT.md) found a false acceptance and a timeout, so no evaluator default or deterministic guard changed.
The gitignored `cache/` holds fetched source-byte snapshots, a shallow CCF git checkout, PDFs, page-one text extracted with `pdfjs-dist`, Nominatim results, LLM responses and a Python `deepeval` virtualenv. Install the evaluator once: `python3 -m venv cache/venv && cache/venv/bin/pip install 'deepeval>=3,<4'`. The original collection run had no hosted evaluator key and used local `codex exec -m gpt-6-luna -s read-only --skip-git-repo-check -o <file> <prompt>`; a key was subsequently verified only for the dated live experiment linked above. Collection uses a polite User-Agent, timeouts and last-good HTTP cache. Overpass POST form requests use city bbox searches filtered against cached Nominatim administrative polygons, rather than rely on mirrors' optional area index; six mirrors include all four requested fallback instances. Nominatim street searches are cached and throttled to one per second. CCF is cloned automatically into `cache/ccf` and refreshed no more than every twelve hours. Failures remain visible in the catalogue (`status: \"failed\"`, `error`), and a failed fetch never means a record was cancelled.

For Jev modes, create the separate ignored DeepEval 4 environment once: `python3 -m venv stadtstack-data/cache/venv-jev && stadtstack-data/cache/venv-jev/bin/pip install 'deepeval>=4,<5' 'typesafe-sdk>=0.7,<1'`. The `jev:check` command validates dependencies and, once an actual key is configured, locally constructs the selected metric without contacting TypeSafe.

## Required Strausberg core release

Pin the core evaluator with `cache/venv/bin/pip install 'deepeval==3.9.9'`; the exact metric version is part of the required judge policy.

`npm run weekend` refreshes/evaluates the three selected assertions and then runs the same whole-dataset publication gates. `npm run evaluate:core -- --from-published` prepares staging only; `npm run publish` validates the complete staged dataset. Partial `--core-only` publication is removed: every release must bind all city and regional files, not just an unchanged three-fact bundle. Normal `evaluate` also requires the core gates; collect-only selected facts cannot be published.

The shared contract is `out/core/strausberg-facts.json` (`stadtstack-core-facts-v1`) plus `out/core/release-manifest.json` (`stadtstack-core-release-v1`). Stable IDs are `lake:straussee-level-2026-09-14`, `budget:investment-outlays-2025` and `budget:investment-outlays-2026`. The lake measurement is **historical**, −1.61 m relative to Normalstau on **2026-09-14**, from the PDF headed **2026-10-05**; the newer document date does not turn it into a current measurement. The two budget assertions are **planned** investment outlays: **17,941,270 EUR (2025)** and **12,609,320 EUR (2026)**. Their document heading remains 2024-11-07, not their retrieval date or the later ordinance publication date.

Each fact retains its assertion/date/unit, original PDF URL and byte SHA-256, exact page/row locator, extractor version, assertion hash, deterministic checks and actual DeepEval `FaithfulnessMetric` evidence from **codex:gpt-6-luna**, threshold **0.8**, ambiguity penalization enabled (metric 3.9.9). No model substitution or LLM rewriting is used. The schema preserves the evidence in full and compact signals; the lake uses `kind:"measurement"`. `reviewState:"auto_checked"` is retained for compatibility; explicit `verification.status:"auto-verified"` means **only that the named automated gates passed**, not human review or independent truth certification. The evidence basis is one primary source per assertion, not cross-source corroboration.

Publication validates **all three assertions and gates before any public output replacement**, including exact corpus equality, original cached PDF hashes, re-extracted row/unit checks, context and statement hashes, and local actual-judge evidence. Missing, failed, altered or stale-to-source evidence aborts publication. The manifest binds bundle file bytes/version, each fact version, source/assertion/evidence hashes and full/compact corpus hashes. The exact bundle is the game/MCP contract, not separately rewritten facts. `out/core/handover-draft.json` is explicitly **not sent** and includes exact release/fact references; poll results and council receipt are null.

Gate caching is keyed by exact source-byte hash, statement/context hashes, extractor version and judge policy; changed input/configuration requires actual re-evaluation. Originals, extracted page text and evaluator working files stay under ignored `cache/`; public files contain only attributed facts and short gate reasons, never the PDFs, secrets or request headers. A fresh cache needs the documented DeepEval environment and authenticated Codex access; an unavailable required model fails closed. Run focused regression checks with `node --experimental-strip-types --test test/core.test.ts` after generation; tests use the actual released evidence, not invented judge scores.


## Phase A quality refresh and release gates

The current priority is the three districts: **big-city backfills are paused and their caches retained**. `npm run quality:refresh -- --retain-city-snapshot` stages the existing city snapshot without council/geodata requests or importing backfill rows. It quarantines unbound/foreign council rows, keeps original source timestamps and marks incomplete/unchecked coverage honestly. Without that flag, the explicitly requested full-refresh capability remains available; it is not part of the current `all` command. `publish` applies the same identity, public URL, date, deduplication and core-evidence gates in either mode.

Optional explicit local inputs:

```sh
npm run quality:refresh -- --retain-city-snapshot \
  --atlas-register /absolute/path/to/strausberg-project-atlas/data/project-register.json \
  --evidence-cache /absolute/path/to/an-existing/stadtstack-data/cache
npm run publish
```

Only the core manifest's named, content-addressed public PDF and actual judge-receipt files are copied from an explicitly supplied evidence cache; no environment/credential files are read. Without it, provision current core evidence using the documented evaluator first. The optional curated Atlas register is local derivation input, not proof its primary citations were fetched. Public method provenance links to pinned committed research, never a fictitious public Atlas API. `--cities` limits a subsequent refresh to comma-separated already-published cities; it does not bypass whole-release gates.

- OParl body names must match configured municipalities/explicit evidenced aliases; pinned body IDs distinguish generic vendor names such as `Instance 0001`. Source binding and scoped council record URLs are independently checked at publication. Düsseldorf selects body **0015**, not the first two bodies from a shared endpoint. Neuss/Mönchengladbach are separate registry candidates, not fabricated new map/feed coverage.
- Council history requests **24 calendar months**, retaining published future meeting/paper announcements separately from that historical window. `quality:refresh` traverses up to 10,000 pages per list with durable page checkpoints and rejects unfinished inventory traversal. Completed lists may be reused for six hours without advancing their original `checkedAt`. Connection interruptions/timeouts receive at most two additional public GET attempts after 15/30 seconds; policy, HTTP and integrity failures are not retried as connection failures. Supported sources use `modified_since`; ignored/rejected filters trigger explicit full reconciliation, never an empty or false incremental-complete result. CCF follows verified live binding/tombstones; archive presence cannot establish city ownership.
- Sources expose collected `recordCount`, `publishedRecordCount`, requested/observed coverage and licence evidence. `ok` with zero records is rejected; genuine empty results, withheld records and auxiliary boundary context have distinct statuses. Unknown licence remains unknown with restrictions/evidence—not a guessed open licence.
- Non-public absolute URLs, credentials and invalid URL schemes fail publication. Documented safe relative catalogue distribution paths are permitted. Local Atlas collection can remain private, but its local endpoint cannot escape into public source metadata.
- Missing/invalid/reversed source event/legal dates are quarantined and counted in `out/quality-report.json`. OSM places use valid observation dates, not invented opening/event dates. Regional null event dates are likewise withheld from dated comparison; source/retrieval/release dates remain distinct.
- Planning identity uses authoritative case/plan keys plus legal dates. Same-case polygon parts and attribution are merged, not discarded; distinct amendments sharing title/day remain separate. Title/date duplicate counts are diagnostics, not a licence to delete distinct cases.
- `out/release-manifest.json` (`stadtstack-data-release-v1`) hashes catalogue, full/compact city records, feeds, deltas, regional topics, core artifacts, knowledge registry/records/coverage and quality diagnostics. Startup verifies this whole release plus the selected-core manifest. These hashes establish integrity within the trusted release, not independent truth or signatures.

## Three-district knowledge pipeline

The official inventory contains 319 municipalities; the detailed pilot comprises Strausberg, Hoppegarten and Rüdersdorf bei Berlin (Märkisch-Oderland), Ratzeburg, Mölln and Schwarzenbek (Herzogtum Lauenburg), and Ludwigslust, Parchim and Hagenow (Ludwigslust-Parchim). Registry presence is not extracted-record coverage. All nine selected municipalities are recorded as amtsfrei; administrative cooperation is not silently treated as Amt membership. Source checks distinguish `checked`, `not_found` and `not_checked`.

The current work is **deepening the frozen nine-pilot corpus, not expanding to 319 municipalities**. Its index hash is `fbcd03c8474e3fa3cb2a3db0b9a976e3793863a3a6e268b0ead21868516ec2c0`: 2,842 representations, 2,390 PDFs and 1,822 municipality/byte groups. Source preparation and Codex `gpt-6-luna` run on `codex-workstation`; native Claude `claude-haiku-5-5` uses the existing first-party Max subscription on the Mac. The exact model is mandatory—no API key, fallback model or auth-file copying. Coding/review agents remain separate from these product extractors.

The owner subsequently authorized **pilot coverage completion** only for Hagenow, Parchim, Schwarzenbek, Ratzeburg and Mölln, using their already-registered council systems, portals and gazettes. Before/after town/source counts and immutable input hashes distinguish this from the original frozen slice. A one-document cache is a collection gap, not evidence that the town has no further documents. Other municipalities, new source providers and policy/authentication bypasses remain excluded.

The reviewed completion snapshot is `fb4e08eee8bf1a3bf036433893553b5ebb0e7ae4dec1fea6ce702a8f66642992`: **5,193 representations, 3,990 PDFs, 4,119 municipality/byte groups**, still nine towns and 41 source identities. The other four towns' original rows/checks are unchanged. [Before/after source counts and limitations](reports/pilot-coverage-completion.json) distinguish existing cache, new collection and three excluded statewide discovery roots. Nine ambiguous mixed-publicness PDFs remain withheld; 21 Parchim records beyond the completed boundary are deferred. Public anonymous Wicket form/AJAX context—not login or bypass—resolved the earlier bare-loader HTTP500.

BOB-SH procedure IDs are joined to exact eight-digit AGS (or a consistent twelve-digit ARS), never town-name or Amt-name substrings. Its versioned bound-seed frontier excludes statewide roots and neighboring procedures while retaining policy-checked linked documents. Missing/conflicting identity cannot fall back to generic seeds. A successful exact-code empty result describes only the observed query scope, not a municipality's whole planning activity.

PDF extraction uses `pdftotext` reading order, not physical `-layout`: the latter interleaved newspaper columns and split source words in the actual Hagenow gazette. The reading-order conversion removed all 109 observed line-hyphenation breaks there without weakening quotation, date, stage or model gates.

Prepare source-bound text on the VM, with its existing `pdftotext`, Tesseract and German/English OCR data. The preparation command verifies frozen bytes and policy before creating private, content-addressed receipts; it prints only receipt-plan identity and counts. Source text and model calls do not belong in logs.

```sh
# On codex-workstation, from the dedicated stadtstack-data directory:
npm run knowledge:prepare-text -- \
  --index cache/pilot-coverage-completion/index-authorized.json \
  --corpus-sha256 fb4e08eee8bf1a3bf036433893553b5ebb0e7ae4dec1fea6ce702a8f66642992 \
  --raw-root cache/districts/raw --max-documents-per-municipality 60
# Transfer the resulting private plan via the existing authenticated SSH link.
# On the Mac, pin the digest returned by the trusted VM command:
npm run knowledge:extract -- --prepared-plan PRIVATE_PLAN_PATH \
  --prepared-sha256 TRUSTED_PLAN_SHA256 --out cache/district-joint
npm run knowledge:usage
npm run knowledge:prepare
npm run publish
```

`knowledge:prepare` defaults to that exact completed index; reproducing the original slice requires its explicit `--index` and matching original registry/run evidence. Both approved snapshot hashes remain pinned. Arbitrary correctly checksummed replacements are rejected.

Preparation prioritizes grounded seeds and content-bearing topical documents over navigation; link-year hints rank work only and never become source dates. `--max-documents-per-municipality` is an explicit work bound, not a claim of complete coverage. Primary document groups are assigned by stable hash roughly half to each provider; an independently hashed approximately 5% sample runs both on identical prepared inputs. OpenAI has at most one VM document worker. `--anthropic-workers 1..4` requests independent local document subprocesses (default 1; current owner-authorized request 4), each retaining the native one-call guard and identical extraction/judgment prompts and gates. One coordinator serializes durable assignments and excludes concurrent work on the same group. Secondary agreement outputs are private comparison evidence, not duplicate published facts. Neither agreement nor same-model scores establish independent source corroboration.

Public source coverage retains full failed-link counts but at most three safe failure examples per source; full frontier diagnostics stay in the private cache. Missing documents and technical limits are not automatically municipal refusal.

Model failures pause that provider and retain pending tasks; work is never silently rerouted. Private task results and model-response caches survive interruption; completed result hashes and source/provider/contracts are checked before new calls. Use `npm run knowledge:control -- --provider anthropic-subscription --action pause` to stop that provider; after resolving the cause, use `--action resume` and rerun extraction with `--resume-provider anthropic-subscription`. A safe coordinator restart can explicitly resume both providers with `--resume-provider anthropic-subscription --resume-provider openai-subscription --anthropic-workers 4`. The internal API accepts `resumeProviders: ExtractorProvider[]`; no failed task is implicitly retried. OpenAI control is forwarded to the authorized VM. Only the owner of an abandoned run/task/group lock may remove it after confirming its recorded process and model descendants are gone.

A single coordinator quota monitor runs `omp usage --provider anthropic --json --no-extensions` at startup and every 30 seconds, never once per worker. It retains only a safe projection in private `worker-quota.json`: `state`, `checkedAt`, `maxUsedFraction`, `limitCount`, `requestedWorkers`, `effectiveWorkers`. Fresh (at most 90 seconds), unambiguous single-account metadata with all limits `ok` and below 80% usage permits the requested capacity. Unknown/unavailable initial metadata caps this run at one; capacity never automatically increases after downshift. A warning, 80% usage, stale metadata, or loss of known metadata after scaling pauses new work; warning/loss writes the existing provider stop marker so concurrent native calls cancel and explicit resume is required. Private `worker-capacity.json` retains requested/effective counts, peak active counts and the safe quota summary. No identifiers or raw reports are written. This metadata monitor does not reinterpret source evidence or change fingerprinted runtime/model contracts.

Each coordinated quota poll first runs `omp usage invalidate --provider anthropic --no-extensions`, then the JSON query above. This bypasses CLI reports whose cache lifetime exceeds the 90-second freshness lease without weakening that lease. Invalidation failure, query failure, malformed JSON or still-stale timestamps remain unknown; cancellation between commands prevents the query. Both subprocesses are individually bounded to 15 seconds, and no invalidation output or raw report is persisted.

Monitoring boundary: successful native Claude advisory/account-warning events that the existing runtime does not expose and that are absent from `omp usage` metadata are **not detected** by this monitor. Native provider failures still use the shared failure marker and cancel sibling calls. Universal advisory detection would require controlled warning classification and pause integration in the fingerprinted native parser/runtime; that change is intentionally excluded to preserve the active prompt contract and caches. Validate live healthy/warning monitoring before activating higher concurrency.

An explicit `--owner-watches-quota` selects the owner's later authorized policy: requested Haiku capacity (up to four) is permitted while `omp usage` has no limit windows. No quota metadata is invented; the private receipt says `policy:"owner-watched"` and `state:"unknown"`. The owner monitors limits directly, so this mode does not run the OMP quota poller. Native rate-limit, usage-limit or authentication errors still pause the provider and cancel sibling workers, and the owner's pause/stop control remains effective. Without this explicit flag the conservative automatic policy above remains the default.

Only an explicit owner-authorized `run --assignment-mode codex-only` changes that assignment policy. This temporary mode was authorized when native Max authentication became unavailable; it processes the same frozen inputs with actual Codex provenance and does not manufacture a dual-model agreement sample. The default remains `balanced`. Mode and input contract are pinned in distinct durable plans and public coverage; completed same-provider results are reused without relabelling another provider's work. Authentication failure itself never selects this mode.

VM and local workers receive a bounded control line and heartbeats every ten seconds (authenticated SSH for the VM, a private parent pipe locally). Connection EOF, malformed input, catchable termination signals or 45 seconds without a heartbeat abort inference, including the active model process group. The coordinator waits for worker termination on cancellation; local workers acquire task/group locks before inference. Private failure receipts retain only controlled categories and error-message digests. A transport checksum cannot authorize another corpus: preparation, coordinator and workers all require the fixed pilot digest.

Native failures also have a private `${ledgerPath}.failures.jsonl` sidecar for **both** providers: source-group/call identity, fixed reason codes, bounded exit status and declaration-versus-attempt tool evidence. Unknown tool kinds are hashed, not accepted. It never stores raw events, stderr, prompts, source text, request/header/account data or credentials. Usage remains separate; missing counts stay unknown. Older failures without such receipts cannot be retroactively diagnosed from unrelated logs.

`knowledge:usage` reports hourly UTC calls, purposes, reported top-level/per-model input/output/cache token counts and CLI API-price equivalents. **These are not actual subscription bills or remaining quota**; unavailable values remain unknown. The original synthetic readiness call is separately labelled and imported once. Ledgers contain no prompts, responses, account IDs, credentials, headers or request objects. Owner pause markers and independent failure markers remain private.

Collection follows permitted scoped links without a fixed depth cutoff. Per-turn defaults are eight documents, three HTML pages and 24 requests; all municipalities get a turn before deeper archives continue automatically. `--max-rounds` bounds an explicit partial run rather than declaring it complete. Conditional rediscovery defaults to 24 hours; unfinished queues and failed links survive restart. Complete means discovered links in the configured scope, not every municipal document. Raw bytes, extraction text, caches, failed candidates and process locks stay under ignored `cache/`.

The crawler uses an identified contact-bearing User-Agent, robots rules, per-host rate control, conditional HTTP and content-addressed bytes. Structured public APIs and XPlanung formats take precedence where actually observed. HTTP/meta/W3C TDMRep reservations and parsed PDF XMP policy are checked before subscription transmission. PDF policy receipts require `pdf-tdm-v2`, including compressed metadata and numeric XML references; earlier cached PDF proofs must be revalidated. Authentication, CAPTCHA, paywall, robots and policy barriers remain explicit `ask_municipality` evidence—not permission to use a mirror or guess an endpoint. §5 official-act and §44b TDM classifications are candidates, not blanket licences or legal approval. Public output is attributed facts, not a republication grant for original documents.

Every admitted record retains the original 17 deterministic checks plus four entity/relation grounding checks and an actual separate model faithfulness judgment ≥0.8. Facts, entities and typed relations are extracted in the **same pass**, not reconstructed from summaries later. Every relation has quoted endpoints/predicate, modality and supported time/conditions; co-occurrence, a project proponent, a budget plan or a future clause cannot become an asserted operator/funding/implementation link. Quotation restoration is limited to lossless whitespace and fully specified calendar equivalence; source-bound action-label normalization never changes quotation text. Original response hashes and source offsets remain evidence. Provider/model/tool identity is recorded per claim; model names/tool hashes are not weights attestations. Codex and Claude isolation is enforced by their native CLI controls and event checks, not a claim of human review.

Both providers use the same draft-07 JSON schema and concise field-binding instructions: approval/award/ownership is not an invented graph predicate, identifiers cannot borrow an issuer from elsewhere, status text preserves source spelling, and summary numbers require their own summary quote. Unsupported optional links/identifiers are omitted; grounded facts are not “repaired” by weakening gates. Claude's `--json-schema` exposes a native `StructuredOutput` return formatter even with operational tools disabled; only that declared formatter and its linked result IDs are permitted. Every other tool/MCP declaration or attempt is rejected. The native [structured-output documentation](https://code.claude.com/docs/en/agent-sdk/structured-outputs) specifies draft-07 support.

The v9 extractor (extraction prompt v8, judge v7) distinguishes `plans/planned`, `decides/decided`, `approves/decided` and `implements/implemented`. Explicit planning or quoted intent to construct is **never** `implements/planned`; decisions and approvals are not execution, expenditure or success. Conditional, negated, proposed and historical qualifiers remain explicit. Deterministic action normalization records the original type/modality, rule and quote/predicate hashes bound to the original source, text and generation response. It is not admission: co-mention, lexical support, time, privacy and all original fact gates still apply.

Cached-triple reassessment uses `node --experimental-strip-types src/district-reassess-relations.ts freeze|judge-pass|merge <CONFIG_JSON> <CONFIG_SHA256>`. Freeze pins the completed work/preparation plans, results, prepared receipts and actual cached responses. Provider-native judge passes may call only the unchanged fact-faithfulness gate for changed/newly passing, date-qualified claims; unchanged failed judgments are not retried. Merge independently checks bindings and keeps original generation model/prompt/time/response provenance, original coverage and separate reassessment artifacts. Missing source dates or failed original gates remain holds, not grounds for extra extraction or automatic promotion.

Publication withholds wholly undated records and entire records containing URL text rejected by the existing public-URL policy, including malformed OCR URLs; it never repairs or strips quotation text to make a record pass. Holds are source-bound and counted individually in private quarantine, while the remaining release still passes the global URL gate. Every individual source, deterministic and model gate is unchanged. Release acceptance requires source-staged evidence in each of the three districts; **all nine towns is an expansion target, not a fact-quality gate**. Every registered town exposes `status` (`gated_records`, `checked_no_gated_records`, or `not_checked`), `publishedRecords` and `datedStagedRecords`; MCP discovery includes the same bounded `recordCoverage`. Missing records do not establish municipal inactivity. Rejected/withdrawn/cancelled/unknown/candidate states are not positive progress, geography remains null without source geometry, and automatic approval is not human or municipal endorsement.

The next release binds `knowledge/graph.json` to the exact admitted-record bytes and recomputes it on validation. Identifier+issuer evidence is strongest; qualified cross-town name groups are explicitly unverified identity matches, while generic local bodies and unnamed projects stay scoped. Distinct legal forms, amendments and conflicting identifiers remain distinct. Public coverage lists admitted model identities/counts rather than pretending both providers produced every record, and exposes frozen-corpus, input-registry, joint-prompt and schema digests. The input-registry digest describes the authorized preparation bytes; released files also have their own whole-manifest byte hashes.

Kair/Braid is a possible **later inbound authorized-bundle source**, not an outbound handover target or a connector in this release. No private bundle/API contract or permission is inferred from its public website.

## Public files

`out/catalogue.json` retains schema `stadtstack-signals-v1`, generated time, publisher and city/bounds/distribution metadata. Each source additionally has collected/published record counts, `coverage` with requested/observed dates and complete/partial/empty/failed/not-checked state, optional verified `bodyBinding`, and `licenceEvidence`. City temporal coverage comes from actual retained dated observations, not a fabricated beginning. `feedUrl`/`minUrl` are relative to the catalogue; `fullBytes`/`minBytes` are exact UTF-8 sizes including the final newline.
- `out/cities/<cityId>/signals.geojson`: GeoJSON with original/full geometry or null; stable id/version, city, kind (`planning`, `construction`, `roadworks`, `council_paper`, `council_meeting`, `budget`, `consultation`, `place`, `measurement`), title/statement/original status, start/end dates, next step, unknowns, scale/precision, sources/extraction/review state and `asOf`. Optional `caseKey` preserves authoritative planning identity; `temporalBasis` distinguishes source events from observations. Selected core facts retain `assertion` and automated `verification`.
- Council `id` is `council:<percent-encoded canonical OParl object URL>` regardless of CCF/git versus live OParl origin; canonicalization equates HTTP and HTTPS and removes trailing slashes. Council records additionally retain optional `upstreamModified` in the full file. When both providers have the same object URL, the newer upstream `modified` record wins and **both** fetched source entries remain in `sources`; compact `sourceCount` reflects that combined provenance.
- `out/cities/<cityId>/signals.min.geojson`: display-only FeatureCollection retaining **every feature id and version** from the full dataset. Coordinates round to five decimals; lines and polygon rings use Douglas–Peucker at ~4 m unless that would invalidate topology. Sub-grid multipolygon components or holes may be omitted; when a valid rounded polygon/line cannot be made, an approximate Point marks its location instead of losing the feature. Properties are limited to `id`, `version`, `cityId`, `kind`, `category`, `title`, `statement`, `status`, `startDate`, `endDate`, `nextStep`, `scale`, `geometryPrecision`, `reviewState`, `asOf`, `sourceCount`, `primarySource` (`url`, `title`, `publisher`, `licence`, `reuse`), and optional `faithfulness` (`score`, `threshold`). The full file keeps original precision, all sources, locators, source hashes, unknowns and review reasoning; fetch a single full record by `id` for detail. The compact projection has **the same source-specific rights**, including ODbL share-alike for the separable OSM subset, and is not separately licensed.
- `sources[]`: `{url,title,publisher,locator,retrievedAt,sha256,snapshot,licence,reuse}`. `sha256` is **only** the actual SHA-256 of fetched source bytes in the gitignored cache, never a URL hash, citation hash or generated content hash. A cited document not fetched has `sha256:null,snapshot:false` (atlas citations). When the citation URL differs from the fetched response URL (e.g. an OSM object from a cached Overpass response), `snapshotUrl` identifies the fetched source. Reuse is `open_licence | official_work | facts_with_attribution | unknown`. The `version` field is instead the hash of normalized derived signal fields.
- `extraction` records structured/LLM method, optional model and faithfulness score/reason/evaluator/threshold. Ordinary council/Atlas candidates are not automatically promoted merely because the separate core assertions passed. A score alone is not human review: promotion requires the named policy and content-bound evidence. Faithfulness checks passage support, not completeness, permissions, location correctness or independent truth.
- `out/cities/<cityId>/changes.json`: `{added:string[],changed:string[],removed:string[],generatedAt}` by id/version versus prior published run. Previous GeoJSON is retained in `out/previous/cities/<cityId>/signals.geojson`. The first canonical-ID cutover reports legacy `ccf:`/`oparl:` identifiers removed and `council:` identifiers added; this is an **identity migration**, not evidence that a proposal was withdrawn.
- `out/knowledge/{registry,records,coverage,graph}.json`: official municipal/source inventory, admitted normalized evidence, explicit crawl/extraction coverage and graph derived from those exact record bytes. Claims preserve topics/hierarchy, original and normalized stages, date roles, authority case identifiers or labelled source-document fallback, entities/relations/locations, hashes and actual gate receipts. All four files are required and bound by the whole-data manifest.
- `out/README.md`: snapshot-level rights, attribution, coverage and as-of caveats. No PDFs, images, full extracted documents or resident coordinates are shipped; bounded source quotations accompany admitted knowledge records.

Each city also publishes `out/cities/<cityId>/feed.json` with schema `stadtstack-feed-v1` (sources and headline/link-only news/events items); the catalogue's `feedUrl` is relative to `out/catalogue.json`. Feed items contain no article body. The feed adapter supports RSS 2.0, Atom and iCalendar, retains news from the previous 45 days and upcoming iCalendar occurrences through 60 days, and currently skips recurrence-rule expansion. Feed licences are recorded as `unknown`; items use `facts_with_attribution`, so headlines are relayed with publisher attribution and links only. A public feed is not a republication licence.

Event items also retain `publisherRecordId`, `venue`, optional GeoJSON Point `geometry`,
`geometryPrecision` and `locationSource` (publisher URL, method, retrieval time, and optional
geometry URL/licence/attribution). ICS `GEO`/`LOCATION` and RSS coordinates are retained.

## Faithfulness calibration and caveats

The faithfulness threshold is `0.8`; production uses DeepEval `FaithfulnessMetric` with `penalize_ambiguous_claims=True` and the Codex judge. A 12-case German calibration improved from 8/12 to 12/12 correct: ambiguity penalization caught four false passes (including “already spent”) without failing the three supported/vague-but-true cases; see [`docs/research/FAITHFULNESS_JEV_EXPERIMENT.md`](../docs/research/FAITHFULNESS_JEV_EXPERIMENT.md). The dated live Jev calibration in that report verified a configured key: `system_one` scored 11/12 at 0.8 (~0.94s per call) but falsely accepted one plan-to-actual claim; `hybrid` scored three cases correctly and timed out on a fourth. The separately supported smoke returned false-low. These experiments did not change the default evaluator or guard. Budget statements contain only the source-supported year, amount and line item; plan-vs-actual context is carried separately in the UI-visible `status` and `unknowns`, outside the faithfulness check. The deterministic budget guard still rejects actual-spending language. The report records two independent evaluator runs for each of the five published LLM statements. Scores are evidence, not legal or human approval; PDF.js may omit scanned or complex layouts.

## Read-only MCP tools

This branch registers **19 read-only tools**: `list_cities`, `list_topics`, `get_core_bundle`, `get_release_status`, `search_signals`, `search_topics`, `get_council_items`, `get_regional_topics`, `search_signals_near`, `search_signals_along`, `get_signal`, `get_sources`, `get_source`, `get_changes`, `compare_topic`, `similar`, `entity_search`, `graph_neighbors`, `graph_path`. The live v0.2.1 release remains the earlier 16-tool release until a new governed rollout; always inspect the endpoint's actual inventory/release.

The next release uses the canonical package version **`0.3.0`** for the literal Git tag, image tag and `serverInfo.version`. `get_release_status.release` exposes `{version,dataManifestId}`; the latter equals the full `dataManifest.id`. The smoke/operator workflow verifies all these identities plus immutable image/source provenance. The old v0.2.1 service's mismatched static `0.3.0` server metadata is not evidence of a 19-tool deployment.

`topic` is a registered subject, not a record type/category. `list_topics` exposes the shared hierarchy, assignment provenance and per-city counts; parent counts include descendants without double-counting records. Existing regional leaf IDs remain stable, including `solarpark`, `waermeplanung` and `haushalt`. Unknown topics/cities/source filters are errors. Catalogue, regional-only and district-evidence coverage remain distinct even though all participate in main search.

Text searches share `query`, `topic`, `recordTypes`, `sourceTypes`, `stage`, `dateFrom`, `dateTo`, `excludePlaces`, `excludeOSM`, `fields`, `limit` and `cursor`; municipality selectors depend on the tool. Source types describe actual families/provenance, not the planning/council record kind. New knowledge records have normalized stages; legacy city statuses remain original statuses and are not silently promoted. `infrastructure` and `unknown` record types remain distinct rather than being relabelled construction.

Pages return `{items,total,nextCursor,withheld,fields}` with default limit 20/max 50. **Offset is removed/rejected.** Reuse the cursor with exactly the same tool/filters/limit/fields; it is signed with a process-only key and bound to the whole release. Restart/release change expires it. Geometry searches use the same projections/paging; buffered lines are capped at 32 vertices. Null-geometry citywide facts are searchable by text/ID, not assigned arbitrary coordinates.

Query records have `sourceIds`, not two embedded attribution arrays. `fields` is an explicit bounded projection allowlist. `get_source({sourceId})` retrieves one source; `get_sources({id})` retains fact/record-ID semantics and returns its single attribution array plus assertion/verification. `get_signal({id})` returns the flat full query DTO. Shared-core auto-verification remains distinct from candidate record status.

`compare_topic({topic,cityIds,...filters})` shows source-backed counts, dated milestones, bounded evidence and municipality-specific coverage, not a performance ranking. Document dates do not substitute for stage dates; future milestones are not achieved progress. `similar({id,cityIds?,topic?,limit?,...filters})` is deterministic cross-city discovery: 0.6 token Jaccard + 0.4 topic Jaccard, with shared terms, evidence and limitations. It uses no model/embeddings/S2Vec and makes no causal or success claim. Quoted case identifiers are counted separately from unresolved source-document groups.

Hosted envelopes use `releasedAt` (whole-data manifest publication time) and `respondedAt` (this response), never ambiguous `date`. Original event/document dates and observation `asOf` remain on the evidence. Lookup-level status is candidate, not an endorsement of every result. MCP only reads immutable released files, never fetches arbitrary sources or performs mutations.

Graph search/neighbors use the same release/filter-bound cursor convention. `graph_path` returns bounded directed shortest paths, at most five hops, over asserted non-action relations, `decides/decided`, `approves/decided` and `implements/implemented`. `plans` is never path-eligible. The response exposes actual returned-edge `modalities` and the explicit `pathEligibility` policy; the obsolete scalar `modality` is removed. Node/edge/path budgets and `truncated`/`status` distinguish an incomplete search from no path. Historical/planned/proposed/conditional/negated links remain attributed neighbor evidence, not factual paths. Paths establish neither causality, independent legal identity nor success.

Protected hosting retains 60 requests/minute/token and four concurrent requests/token. HTTP 429 retains `Retry-After` and includes matching `retryAfterSeconds` and documented limits in JSON. Use cursors/projections rather than burst retries. The protected endpoint/credential/operator guide is [docs/HOSTED_MCP.md](docs/HOSTED_MCP.md); `mcp:http` remains loopback-only development, not the public service.

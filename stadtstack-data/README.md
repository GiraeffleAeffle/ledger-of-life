# Stadtstack Data

Standalone Node.js ≥22 city-data collector and read-only open-data/MCP publisher. No Next.js dependency and no resident location is collected or persisted. All outputs cover a **whole city**, including road corridors up to ~25 km outside its bounds; resident-home filtering must happen on the resident's device. The optional MCP spatial searches see the query **where the MCP runs**: on a local machine, it stays local; a hosted MCP operator would see the coordinates submitted to that host.

The reviewed **0.3.2** donor is released and publicly accepted. R1 incorporates that source while retaining its knowledge-v3, native admission, parser isolation and all-surface serving contracts; the merge itself is not a new R1 data release or deployment receipt. Tracked `out/` remains historical evidence. Serving R1 requires its own complete governed release and authorization, not a package-version change or reuse of the donor's deployment claim.

### Offline crawl-to-residual import

Registry/robots approval is not corpus approval: the existing eight production hashes remain unchanged; no new nine-town corpus is authorized by this implementation.

```sh
npm run knowledge:r1 -- import-crawl-corpus \
  --registry-config "$REGISTRY_DESCRIPTOR_JSON" \
  --registry-config-sha256 "$REGISTRY_DESCRIPTOR_SHA256" < "$IMPORT_MANIFEST"
```

Select 1–200 distinct originals. Each job requires `maxDocuments: 1`, `maxChunks: 1–24`, `maxModelCalls: 2–48`, `paidMicroUsd: 0`. Indexes are bounded to 64 MiB/10,000 originals and observation/request proofs to 1 MiB each. ZIP/GML containers are not converted into fabricated text.

Import authenticates exact registry plus complete original/negative HTTP ancestry, retains index/observation bytes and original retrieval/check clocks, and checks selected managed bodies against their original observation hashes. Current opt-out/shared policy is rechecked; a new PolicyReceipt expires no later than one hour after the oldest actual robots/TDM/representation evidence. Missing clocks or stale policy hold that original; import never refreshes evidence timestamps. Missing complete ancestry holds the entire selection rather than duplicating an incomplete index. Actual request method/URL/content type, body digest/public selector and redirect chain live in an independently pinned managed sidecar at `${rawRoot}-request-evidence/requests/<original-observationId>`, bound to the exact original observation. Legacy observations lacking a sidecar hold for import only; their byte format and existing processing are unchanged. No request headers or account credentials are recorded.

Originals with identical bytes may share a CAS path while retaining distinct HTTP observations. Execution selects the exact active, independently permitted HTTP admission for that original and rechecks its body digest and current opt-out state; corpus and request artifacts still require exact complete provenance sets. Request evidence records the canonical URL actually dispatched, including the canonical initial redirect endpoint. If sidecar capture fails after a successful source admission, it raises a content-free `CrawlRequestEvidenceCaptureError` without converting the fetch to a network/source failure or rewriting its successful observation.

#### Governed current-policy refresh for frozen originals

Expired crawl evidence is not renewed by offline import. Under a **separate explicit source/network authorization**, enqueue `knowledge:r1 enqueue-policy-refresh` with the same registry flags and stdin `{manifest: <CrawlCorpusImportSchema>, maxRequests: 2..100}`. The offline preflight authenticates the full frozen index, exact selected original observations, source scope and genuine request sidecars; it returns `{jobKeys: [{documentId, jobKey}], holds, coverage}`. Authorize those actual `policy_refresh` keys and run through the existing bounded executor/notification path, with authorization expiry, elapsed time, job count and per-job request bounds. Model approval #81 alone does not authorize another acquisition.

The refresh job uses **the same public PoliteFetcher path, honest UA, opt-out gates, host scheduler and R1 capacity lane** as acquisition, requesting current robots and standardized/configured TDMRep evidence only. Conditional requests/304 retain the policy representation's original retrieval time and add genuine new check observations. In-memory policy TTLs never substitute for a current request in this step. The original document is **not refetched**, and its body, original HTTP observation, request/redirect evidence, body-specific rights findings and clocks remain unchanged. A changed robots/TDM policy representation (including a permissive byte change), declaration, absence status or matching rule holds the document; an objection also holds immediately. Missing/unavailable policy evidence does not become permission.

After a committed successful refresh, add only its actual `policyRefreshJobKey` to the corresponding original `documents[]` selection and rerun **offline** `import-crawl-corpus`. Uncommitted/held/mismatched/expired refreshes return holds, never a fallback to the old expired proof. The receipt expires **one hour after the oldest current robots/TDMRep observation**; body-bound historical findings retain their old clocks. Enqueue/preparation/extraction keep their current-time receipt checks. A refresh success is not a guarantee that a long model batch will finish within that window; no automatic renewal or retry is introduced.

# Stadtstack Data

Standalone Node.js ≥22 city-data collector and read-only open-data/MCP publisher. No Next.js dependency and no resident location is collected or persisted. All outputs cover a **whole city**, including road corridors up to ~25 km outside its bounds; resident-home filtering must happen on the resident's device. The optional MCP spatial searches see the query **where the MCP runs**: on a local machine, it stays local; a hosted MCP operator would see the coordinates submitted to that host.

## Run

```sh
npm install
npm run collect -- --city all          # or --city strausberg / koeln / ...
npm run evaluate                      # PDFs + Codex + DeepEval
npm run publish                       # validates before replacing outputs
npm run all                           # the three steps above
npm test
npm run mcp                           # stdio
npm run mcp:http                      # Streamable HTTP http://127.0.0.1:4318/mcp
```

The gitignored `cache/` holds fetched source-byte snapshots, a shallow CCF git checkout, PDFs, page-one text extracted with `pdfjs-dist`, Nominatim results, LLM responses and a Python `deepeval` virtualenv. Install the evaluator once: `python3 -m venv cache/venv && cache/venv/bin/pip install 'deepeval>=3,<4'`. No API keys were present in this run, so the provider is local `codex exec -m gpt-6-luna -s read-only --skip-git-repo-check -o <file> <prompt>`. Collection uses a polite User-Agent, timeouts and last-good HTTP cache. Overpass POST form requests use city bbox searches filtered against cached Nominatim administrative polygons, rather than rely on mirrors' optional area index; six mirrors include all four requested fallback instances. Nominatim street searches are cached and throttled to one per second. CCF is cloned automatically into `cache/ccf` and refreshed no more than every twelve hours. Failures remain visible in the catalogue (`status: \"failed\"`, `error`), and a failed fetch never means a record was cancelled.

## Public files

- `out/catalogue.json`: `{schemaVersion:"stadtstack-signals-v1",generatedAt,publisher,cities:[{id,name,state,center:[lon,lat],bbox:[w,s,e,n],sources:[{id,kind,publisher,url,licence,reuse,retrievedAt,status?,error?}],temporalCoverage?,spatialCoverage?,licence?,minUrl,fullBytes,minBytes}]}`. `minUrl` is relative to `out/catalogue.json`; `fullBytes` and `minBytes` are exact UTF-8 file sizes, including the final newline.
- `out/cities/<cityId>/signals.geojson`: GeoJSON FeatureCollection. Each Feature has `geometry` Point, LineString, Polygon, MultiPolygon or `null`, and `properties` with `id` (`<sourceId>:<upstreamId>`), `version` (SHA-256 of normalized content and evidence hashes, not retrieval time), `cityId`, `kind` (planning, construction, roadworks, council_paper, council_meeting, budget, consultation, place), `category`, `title`, `statement`, `status`, `startDate`, `endDate`, `nextStep`, `unknowns`, `scale` (street, neighbourhood, city, district, state, national), `geometryPrecision` (exact, approximate, area, none), `sources`, `extraction`, `reviewState` (candidate, auto_checked, reviewed, rejected) and `asOf`.
- Council `id` is `council:<percent-encoded canonical OParl object URL>` regardless of CCF/git versus live OParl origin; canonicalization equates HTTP and HTTPS and removes trailing slashes. Council records additionally retain optional `upstreamModified` in the full file. When both providers have the same object URL, the newer upstream `modified` record wins and **both** fetched source entries remain in `sources`; compact `sourceCount` reflects that combined provenance.
- `out/cities/<cityId>/signals.min.geojson`: display-only FeatureCollection retaining **every feature id and version** from the full dataset. Coordinates round to five decimals; lines and polygon rings use Douglas–Peucker at ~4 m unless that would invalidate topology. Sub-grid multipolygon components or holes may be omitted; when a valid rounded polygon/line cannot be made, an approximate Point marks its location instead of losing the feature. Properties are limited to `id`, `version`, `cityId`, `kind`, `category`, `title`, `statement`, `status`, `startDate`, `endDate`, `nextStep`, `scale`, `geometryPrecision`, `reviewState`, `asOf`, `sourceCount`, `primarySource` (`url`, `title`, `publisher`, `licence`, `reuse`), and optional `faithfulness` (`score`, `threshold`). The full file keeps original precision, all sources, locators, source hashes, unknowns and review reasoning; fetch a single full record by `id` for detail. The compact projection has **the same source-specific rights**, including ODbL share-alike for the separable OSM subset, and is not separately licensed.
- `sources[]`: `{url,title,publisher,locator,retrievedAt,sha256,snapshot,licence,reuse}`. `sha256` is **only** the actual SHA-256 of fetched source bytes in the gitignored cache, never a URL hash, citation hash or generated content hash. A cited document not fetched has `sha256:null,snapshot:false` (atlas citations). When the citation URL differs from the fetched response URL (e.g. an OSM object from a cached Overpass response), `snapshotUrl` identifies the fetched source. Reuse is `open_licence | official_work | facts_with_attribution | unknown`. The `version` field is instead the hash of normalized derived signal fields.
- `extraction`: `{method:"structured"|"llm",model?,faithfulness?:{score,reason,evaluator,threshold}}`. An LLM-supported claim scoring at least `0.8` is `auto_checked`, **never reviewed**. Structured authoritative data may be auto-checked; atlas projects and council records remain candidate without human review. Faithfulness checks support against a passage, not completeness, correctness of location, permissions or independent truth.
- `out/cities/<cityId>/changes.json`: `{added:string[],changed:string[],removed:string[],generatedAt}` by id/version versus prior published run. Previous GeoJSON is retained in `out/previous/cities/<cityId>/signals.geojson`. The first canonical-ID cutover reports legacy `ccf:`/`oparl:` identifiers removed and `council:` identifiers added; this is an **identity migration**, not evidence that a proposal was withdrawn.
- `out/README.md`: snapshot-level rights, attribution, coverage and as-of caveats. No PDF, images, extracted paper text or resident coordinates are shipped.

Duplicate audits also compare title + calendar date + kind, but **do not erase records on those fields alone**: separate Köln plan geometries, distinct Autobahn roadwork segments and different council bodies may share a title/day. A nearby OSM node and way with the same normalized name and category within 50 m represent one place: the node's position is retained and both ODbL source entries remain attributed. Distinct nearby OSM names/categories and farther places remain separate.

The eight pilots are `strausberg`, `koeln`, `muenster`, `wuppertal`, `castrop-rauxel`, `duesseldorf`, `dresden`, `freiburg`. `src/cities.ts` also keeps verified endpoint registry entries for Krefeld, Solingen and Kerpen; source adapters are city-independent. Atlas `/api/atlas/<city>` and `/map` are used for curated draft projects. OSM via Overpass supplies unverified everyday places under ODbL 1.0 attribution and database obligations; OSM-derived features are separable by `id` prefix. Autobahn roadworks/closures are included near the city bounds; API licence **unknown**, so facts are attributed rather than asserting an open licence. CCF git and live OParl provide recent council papers and meetings; an agenda or paper is **not** a decision, and paper reuse is always facts-with-attribution. The Strausberg §1 budget ordinance is an official work (§5 UrhG); 2025/2026 investment outlay figures are *plans*, not evidence of spending. Third-party PDF text/images are not republished.

`src/geodata-registry.ts` configures source-type adapters for Cologne's ArcGIS binding B-Plan layer (1,561 plans, including historical plans with no geometry) and works WFS (three classes), and Münster's legal-plan and roadworks WFS. GetFeature/page caps bound downloads. WFS prefers GeoJSON, with GML fallback; coordinate output is transformed to EPSG:4326 where services mistakenly report projected ETRS89/UTM32 coordinates. Cologne plans/works are `dl-de/zero-2.0`; Münster's two datasets are `dl-de/by-2-0` with `Stadt Münster` attribution in every record. Binding plan outlines show legal planning status, not new construction; recent five-year Cologne plans use neighbourhood scale, older ones city scale. Köln permits describe authorized intervals, not confirmed works. Münster multipart road lines are represented by their longest segment with approximate precision. Düsseldorf's old 2020 traffic records are deliberately not published.

## Faithfulness calibration and caveats

The faithfulness threshold is `0.8`. On a short ordinance §1 excerpt, a supported *planned* amount scored `1.0`; swapped 2025/2026 amounts scored `0.0` and failed. An unsupported assertion that the planned amounts had *actually been spent* still scored `1.0` against an excerpt that did not explicitly mention actual spending. Budget publication therefore independently requires plan wording and rejects actual-spending language: **DeepEval alone does not establish plan-versus-actual status**. The evaluator is Python `FaithfulnessMetric(actual_output, retrieval_context=[page-one source text])` with the same Codex provider. Scores in published records are checkable evidence, not legal or human approval. PDF.js text extraction may omit scanned or complex layouts. At most ten recent CCF PDF attachments per council are attempted to produce one evaluated sample; failures leave structured candidates intact. HTML sources are not crawled, so robots.txt does not apply here.

## Read-only MCP tools

`list_cities`; `search_signals_near(cityId,lon,lat,radius_m,kinds?)`; `search_signals_along(cityId,line:[[lon,lat],...],buffer_m,kinds?)`; `get_signal(id)`; `get_sources(id)`; `get_changes(cityId)`. Spatial searches return full signal Features with exact sources, precision, review status, as-of. Changes return stable ID arrays, not duplicated city-sized Feature payloads; retrieve current records via `get_signal` and removed records from `out/previous/`. Null-geometry citywide records are intentionally not assigned to arbitrary nearby points; retrieve by id or process the citywide collection separately. MCP only reads published files and cannot fetch or mutate source documents.

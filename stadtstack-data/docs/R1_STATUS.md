### GENESIS credential custody and documented header convention

The trusted host reader uses only `/home/max/.config/stadtstack/regionalstatistik/credentials.json`, never a CLI flag, environment variable or registry selector. The owner provisions that file privately (do not paste values into chat, tickets or shell commands). It must be a regular non-symlink file owned by the executing UID, exactly **0600**, under a same-UID non-symlink **0700** parent; maximum **16 KiB**. The reader pins the parent descriptor, opens the file with `O_NOFOLLOW`, bounds the read and rechecks metadata. Accepted objects have exactly one `token` string or exactly `username` and `password` strings; no GAST account, extra fields, empty values or invalid HTTP scalars.

Header convention: the [GENESIS webservice introduction](https://genesis.destatis.de/datenbank/online/docs/GENESIS-Webservices_Einfuehrung.pdf) describes username/password authentication and token authentication by putting the API token in **`username`**, leaving **`password` empty**. The [Regionalstatistik REST WADL](https://www.regionalstatistik.de/genesisws/rest/2020/application.wadl) defines the existing `username`/`password` headers and POST selectors. The shared GENESIS manual applies analogously; a token must be the owner's **Regionalstatistik** token, not a Destatis token. These are protocol references, not a new live credential/token-success observation; no source/network request is authorized by this code change. The existing `genesis_guest` selector name describes the fixed native selector profile, not the credential mode: the observation's `credentialKind` explicitly distinguishes token from account/password.

Credential values remain private host memory and those two request headers only; no parser/child environment, argv, logs, error causes, policy evidence, receipts, observations, CAS, PG rows or notifications receive them. Credential bytes read from disk are cleared; JavaScript strings cannot be reliably zeroed. Before inspection, scratch writes or source retention, the host secrecy gate validates JSON and scans every unescaped key/string token (including overwritten duplicate keys), bounded-inflates every ZIP member and scans every member name and UTF-8/Latin-1 text, and decodes/scans CSV cells. Selected response headers are scanned raw and fully percent-decoded to a bounded fixed point, before any derived observation field is populated. Echoes, unsupported formats, malformed decoding or screen limits yield a content-free **hold**, never redaction followed by admission; authenticated errors are reconstructed without causes. Authenticated redirects are refused before a destination request.

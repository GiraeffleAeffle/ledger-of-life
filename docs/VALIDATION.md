## Toolchain and dependency observations

- Node 25.2.1 was used locally; Node 24 LTS is the documented and CI target. Local `node:sqlite` emits an experimental-feature warning. Hosted operation uses PostgreSQL rather than ephemeral local storage.
- TypeScript is pinned to 5.9.3 for the Solana Kit/Privy dependency combination, and ESLint to 9.39.5 for the Next plugin. Dependencies are recorded in the lockfile.
- The lockfile was repaired using npm 11.19.0 (the Node 24 CI runner version) to include optional Emnapi runtime dependencies that the older local npm omitted. Linux clean-install validation remains part of CI.
- The final npm advisory check reports **23 moderate, zero high and zero critical findings** in the transitive dependency tree. A compatible `ws` patch override removed the previously reported high finding. The remaining advisories, including provider-wallet dependencies, require review before production. Do not apply an unreviewed major-version audit fix merely to clear the count.
- The build warns that Privy's optional `@farcaster/mini-app-solana` module is absent. This app does not enable Farcaster mini-app login; ordinary account hooks compile. A real configured-wallet rehearsal is still required, and the warning is not concealed as a passing provider test.

CI runs application tests/lint/build and local HTTP acceptance, local EVM tests plus the compiled runtime fingerprint check, Rust host tests, and a separate SHA-256-pinned Agave SBF build with all four LiteSVM tests. The network fork has separate documented replay requirements; a host test is not counted as an SVM execution test.

[Test-signer mode](TEST_SIGNER_MODE.md) runs devnet cycles with operator-held test keys through the real services. On 2026-09-25 one run on the historical staged program completed setup → funding → Kamino supply/redemption → zero claim → settlement (10 test USDC returned). A second run on the separately deployed [pull-v2 program](evidence/SOLANA_PULL_DEVNET_DEPLOYMENT_2026-09-25.json) completed the same path with a 2-test-USDC claim, then settlement recorded owed amounts and two independent `payout` transactions paid 8 test USDC to the tenant ATA and 2 to the landlord ATA (final nonce 8, escrow empty). Test-signer runs are fixtures. They are **not** Privy, wallet or user evidence and are excluded from the claims above.

## Not yet verified

The user completed passkey signup on `localhost`, linked a verified backup email and created EVM and Solana embedded wallets. The browser-driven identity check passed the server's Privy token, current-user and sole-owner wallet verification, then recorded the original-wallet baseline. The user completed backup-email login in Chrome, approved both recovery signatures and received a persisted same-wallet proof that the enrollment browser independently displayed on refresh. A later user-reported physical-phone rehearsal produced the same two-wallet server proof from a different browser and Privy session. A distinct Privy-backed Solana tenancy finalized joint initialization, funding and Kamino supply of 10 test USDC. A separate agreement finalized **staged setup, funding, supply, redemption, zero-claim acceptance and full tenant payout** through distinct Privy signatures. Eligible live stock-token buy/sell fills, earned yield, personal cash exit beyond the returned deposit, fiat banking, hosted database durability, production operations and independent security review remain open. The operator-key devnet proof does not close those gaps. The first signup on the former `127.0.0.1` origin failed before a device prompt; a `localhost` retry returned `disallowed_login_method` until the separate Privy passkey-sign-up option was enabled. Account readiness no longer waits for wallet connectors before showing setup actions. Privy's email modal emitted a non-fatal `stacked` DOM-prop warning; the app now filters just that prop on HTML elements. None of the remaining proofs is inferred from the demonstration, public source visibility, an API key or a price quote.
